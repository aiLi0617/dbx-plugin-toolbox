## 4. DBX 风格一致性

### 4.1 修复前发现

部分组件仍包含固定蓝色、红色或金色的十六进制回退值；Cron、加密等页面的持久选中态也没有统一使用 DBX 的“主色 + 主色前景色”组合。默认主题下不一定明显，但切换暗色主题或宿主自定义主题时会出现选中态对比度和品牌色不一致。

### 4.2 已完成修复

- 新增 `--dbx-selection-background`、`--dbx-selection-foreground`、`--dbx-selection-border` 三个别名，直接追随宿主注入的 DBX 主色令牌。
- 统一按钮、标签页、Cron 选项、加密模式、导航激活态等持久选中状态。
- 将错误、成功、警告、焦点环和收藏状态改为对应 DBX 语义令牌。
- 移除组件内会覆盖宿主主题的固定蓝/红/金色回退。
- 为 Cron 表达式类型补充 `aria-pressed`，让视觉状态和语义状态一致。
- 新增主题令牌回归测试，防止后续重新引入固定品牌色。

### 4.3 修复后验证

| 场景 | 选中态背景 | 选中态文字 | 结论 |
| --- | --- | --- | --- |
| DBX 明色主题 | `rgb(37, 99, 235)` | `rgb(255, 255, 255)` | 与 `--color-primary` / `--color-primary-foreground` 一致 |
| DBX 暗色主题 | `rgb(96, 165, 250)` | `rgb(24, 24, 27)` | 与 `--color-primary` / `--color-primary-foreground` 一致 |

结论：修复后页面视觉语言与 DBX 统一，且不再只适配当前默认配色。

## 6. 可继续优化的地方

### P1：降低首屏 JS 体积

当前生产 JS 约 4.78 MB（gzip 约 1.37 MB），Vite 已给出超过 500 kB 的告警。仓库当前通过 `inlineDynamicImports: true` 将代码保持为单模块，以满足 DBX 只允许 inline/blob 脚本的 CSP，因此不能直接套用普通站点的分包方案。

建议按以下顺序推进：

1. 先用 bundle analyzer 定位 Excel、二维码/条码、Prettier、格式化器等重依赖占比。
2. 与 DBX 宿主确认是否可允许受控的插件资源 URL 或 blob 动态模块。
3. CSP 能力具备后，再按工具页拆分重依赖；否则优先替换体积较大的依赖或将低频能力下沉到后端。
4. 建立首屏 JS/gzip 预算，避免包体继续无感增长。

### P1：补充浏览器级自动化回归

本轮页面测试通过 DBX 调试壳执行，建议固化为可重复的浏览器测试，至少覆盖：38 页打开、控制台错误、主题切换、工具搜索、收藏/最近使用、关键转换向量、可访问名称和横向溢出。

### P2：增加受控文件夹具场景

为图片、XLSX、文件哈希、Data URI 文件和二维码识别准备仓库内无敏感信息的小型固定夹具，并在浏览器测试中覆盖上传、处理、导出和错误文件。这样可把本轮“控件 + 底层算法”覆盖提升为完整端到端覆盖。

### P2：引入标准化可访问性扫描

本轮已修复可见控件名称问题，后续可接入 axe-core 一类规则集，继续检查颜色对比度、焦点顺序、标题层级、动态状态播报和键盘闭环。

### P3：补充性能和超大输入基线

针对大 JSON、大表格、长文本 Diff、超长正则结果和大图片建立固定耗时/内存基线，并记录允许阈值，避免后续功能扩展导致明显回退。
