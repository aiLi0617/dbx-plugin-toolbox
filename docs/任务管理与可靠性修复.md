# 任务管理与可靠性修复

日期：2026-10-22。仅修改源码与本地构建，未发布新版本或覆盖 Release 资产。

- PDF 清除处理结果不再取消已上传的会话。九项原生操作可重复执行，无需重复上传。
- PDF 页面销毁、上传取消、迟到的上传结果均会释放对应会话；处理中的文件待操作停止后删除。
- 非敏感工具最多保留最近使用的 8 个页面，重新访问会更新保留顺序；淘汰页面会销毁组件、Worker 和缓冲。被淘汰页面再次打开时输入重置。

- CI 增加国际化门禁、Windows Rust 检查和真实 Sidecar 集成测试。

## 任务管理

工作台右下角在产生任务后显示任务管理入口，提供排队、阶段进度、耗时、取消及结束记录清理。记录只在当前工作台会话保留，最多保存 20 条结束记录；不保存文件内容、路径、密码、错误详情或处理结果。

PDF、GIF、OCR 识别和 OCR 模型下载分别限制为同类一次运行一个任务。不同类任务可同时执行。排队任务可直接取消；工具页面销毁会取消属于该页面的任务，不影响其他页面。

- **PDF 原生处理**：上传按字节报告进度；读取、处理、拆分和写入报告阶段或已完成文件数量。宿主请求超时后查询原任务状态，不重复提交操作。Rust 解析单个文档和单次文档序列化无法中途打断，取消期间显示正在清理，到下一个检查点才完成取消。
- **PDF 前端处理**：解析、水印、页码、视觉签名和数字签名检查放入可终止 Worker；页面渲染取消会销毁渲染器。
- **GIF**：解码、变换和编码报告实际帧数进度；取消终止 Worker，重试会从当前原文件恢复，不要求重新选文件。
- **OCR**：识别与模型下载接入统一任务记录；继续使用原有分块传输、原生取消和模型完整性校验。模型会话建立期间取消，也会在收到会话编号后释放它。

## 验证

`node --test tests/*.test.js` 运行前端与任务管理测试。

`cargo test --locked --manifest-path backend/Cargo.toml` 包含九项 PDF 原生操作、取消后文件清理及失败状态恢复。

先 `cargo build --locked --manifest-path backend/Cargo.toml`，再设置 `TOOLBOX_SIDECAR` 为二进制绝对路径并执行 `node --test tests/native-pdf-integration.test.js`，验证真实组件处理函数 → Host Bridge 参数克隆 → 二进制上传 → Rust 处理。普通前端测试未设置该变量时明确跳过此项；三个平台的后端 CI 必须执行。

浏览器开发宿主已验证 PDF 水印 Worker 输出、GIF 编解码、任务取消及重试。此验证不等同于真实 DBX 桌面安装验收。
