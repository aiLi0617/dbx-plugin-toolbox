# DBX 宿主能力映射与验证

核对日期：2026-10-23。来源为本地 DBX 插件技能的 Host API、贡献点契约，以及本项目 manifest 和实际开发宿主。未修改发布权限或新增贡献点。

| 场景 | 契约能力 | 本项目状态 | 结论 |
| --- | --- | --- | --- |
| 查询结果传给工具箱 | `result-view` 使用有界 `context.result`，包含 columns、rows、truncated；最多 500 行 | 当前只声明 workbench；未声明 result-view | 受限；需真实桌面验证，不承诺完整结果集 |
| 选中文本菜单进入工具 | 当前 `context-menu` 仅支持已保存连接菜单，后端接收连接摘要 | 没有文本选区贡献点 | 当前契约不支持所设想的文本菜单 |
| 文件入口获得本地引用 | 浏览器 File 输入可选本地文件；文件系统贡献点不是任意 OS 文件菜单 | 已有本地 File 输入、分块二进制通道 | 本地选文件路径可用；系统文件菜单集成未验证 |
| 工作台导航参数 | JSON 快照，上限 2 MiB；不允许函数、Proxy 或凭据 | 现有 context 只用于安全导航 | 不承载工具正文；正文走会话内通道 |
| 二进制处理 | `host.binary` + `stdio-framed` | 已声明，并以真实 Sidecar 验证 PDF 分块操作 | 当前可用 |
| 关闭前拦截 | 需要宿主明确支持；iframe 的 beforeunload 不保证拦截宿主关闭 | 已注册浏览器可支持的提示 | 真实桌面待验收，不保证关闭后恢复 |

## 可运行验证

`node scripts/probe-host-integration.mjs` 检查本地 manifest 和合成结果快照，明确输出 `mode: contract-fixture` 与 `desktopVerification: pending`，不冒充真实宿主验收。

“设置 → 诊断信息 → 复制脱敏诊断信息”同时执行只读桥接能力清点；只输出 API 是否存在及结果快照行数，不复制 SQL、结果内容、连接资料或路径。

真实桌面后续验收使用专门的无敏感数据连接，分别验证完整／截断查询结果、工作台开关、文件选择与取消、不同宿主版本行为。只有这些操作通过后，才考虑新增 result-view 入口；本轮不增加权限或对外承诺。
