# DBX 工具箱与 Oltool 对比及后续实施计划

> 实施状态更新：下文保留实施前的对比基线。当前扩展已接入 52 个新入口，目录共 147 条定义、141 个可见入口（117 个工具、24 个快捷入口）。当前功能名称、组织方式与限制以[扩展功能实施说明](工具箱功能扩展-实施说明.md)为准；Wi-Fi 为独立页面，GIF 保留动画生成并增加三个入口，PDF 各功能独立入口，OCR 不扩展。

> 复核日期：2026-10-21<br>
> 对比对象：[Oltool 程序员工具箱](https://oltool.net/)<br>
> 本地项目：`dbx-plugin-toolbox`（复核时版本 `0.1.5`）

## 1. 本次复核结论

Oltool 首页仍展示 **158 个工具、9 个分类**。本项目已经不再是原文所述的“64 个工具入口”：当前 `src/lib/toolCatalog.js` 中共有 **95 条定义**，其中 **89 个可见启动入口**，由 **69 个独立工具入口**和 **20 个能力快捷入口**组成；另有 6 个仅作为父级工作台存在的隐藏定义。

两边的颗粒度仍然不同，不能直接用“158 对 89”判断覆盖率。按 Oltool 的 158 个页面逐项检查当前实现后，本次采用以下口径：

| 状态 | 数量 | 含义 |
| --- | ---: | --- |
| 已覆盖 | 99 | 已有等价核心能力，允许入口组织、交互和附加选项不同 |
| 部分覆盖 | 6 | 已有相关能力，但缺少 Oltool 页面中的关键方向、数据范围或专用交互；OCR 仅记录差异，暂不扩展 |
| 未覆盖 | 53 | 没有等价功能，或现有相邻工具不能完成该任务 |

因此，当前项目对 Oltool 的**核心能力覆盖约为 63%**；若将部分覆盖计入，相关能力触达约为 **66%**。这些数字是基于源码与对方公开功能描述的分类评估，不代表逐项运行验收或完整选项对等。该数字只用于路线排序，不应作为产品 KPI：本项目在本地密钥库、现代密码学、文件魔数识别、端口进程安全终止、电子表格编辑、图片切图与像素化等方向也有 Oltool 没有的能力。

### 与 2026-10-12 旧结论相比

- Oltool 的首页总数仍是 158，没有出现计数层面的扩张。
- 本地目录已从旧文档记录的 64 个入口变为 89 个可见入口；增加量主要来自密码学能力细分和快捷入口，不能等同于新增 25 个独立工作台。
- 原 P1 中的 **MIME 双向查询、随机可用端口、图片圆角、图片边框**已经实现，应从待办移除。
- **Basic Auth** 按新增功能规划：输入用户名、密码，生成 `Authorization: Basic …`；cURL 参数转换不算已有专用功能。
- **Figlet** 尚未实现。现有 ASCII 方框横幅不具备 Figlet 字体渲染能力，应列为缺失。
- **Numeronym** 已在文本处理的“转换”分组实现正向生成，并接入搜索；没有独立工具入口，按部分覆盖记录。
- **OCR 暂不扩展**：保留现有能力与维护，仅记录语言覆盖差异。
- README 仍写着“9 类、64 个工具入口”，与当前目录不一致，属于需要先修正的文档债务。

## 2. 计数与证据

### 2.1 外部基线

复核时 Oltool 首页声明：

- 158 个开发者工具；
- 9 个分类；
- 所有处理在浏览器本地完成。

本次以首页实际列出的 158 个唯一工具链接为清单，不按描述中的子功能重复计数。

### 2.2 本地基线

本地计数直接来自 `TOOL_DEFS`：

```text
全部定义             95
可见启动入口         89
  独立工具入口       69
  能力快捷入口       20
隐藏父级工作台        6
```

这里的“快捷入口”会锁定父工作台的某个算法或预设，例如 RSA-OAEP、Argon2id、AES-CMAC；它们是有价值的可发现入口，但不应在架构规模评估中被当作完全独立页面。

本地权限仍为：

```text
host.binary
host.events
```

没有声明 `host.network:*`。继续扩展工具时应保持权限最小化；Sidecar 自身具备当前用户进程的网络能力，不能把“未声明前端网络权限”表述成完整的操作系统网络沙箱。

## 3. 已覆盖的主要能力

以下只列能力族，不机械复述 99 个页面。

### 3.1 数据、编码与开发

- JSON 格式化、压缩、树形查看、JSONPath、JSON Schema 和多语言类型生成。
- JSON、YAML、CSV、TSV、NDJSON、XML、TOML 等格式互转。
- SQL、XML、YAML、HTML、CSS、JavaScript、TypeScript 格式化。
- Base64 / Base32 / Base58 / Hex / 二进制、URL、HTML 实体、Unicode、Data URI、Punycode、Quoted-Printable、NATO。

- MIME / 扩展名双向查询，以及按文件内容识别真实格式并检查扩展名伪装。

### 3.2 文本、计算与网络

- 文本清理、排序、去重、替换、命名转换、统计、脱敏、邮箱与 URL 提取。

- 端口占用查询、安全终止，以及由系统实际绑定验证的 5 个空闲端口推荐。

### 3.3 安全、生成器与媒体

- MD5、SHA、SHA-3、SM3、CRC32、HMAC、JWT、TOTP。

- 图片裁剪、缩放、旋转、翻转、水印、圆角、边框、压缩、格式转换、取色、ICO、切图、像素化、Base64、拼接和图片转 GIF。

## 4. 部分覆盖：应优先补完整，而不是新建重复页面

| Oltool 能力 | 当前项目状态 | 建议补齐 |
| --- | --- | --- |
| Numeronym | 文本处理 → 转换 → 数字缩写，支持正向生成；没有独立目录入口 | 可复用现有实现增加专用入口；“反查原词”只能做候选提示，不能承诺唯一还原 |
| 英文单复数 | 仅做规则化复数生成 | 增加单数化、不规则词和不可数名词 |
| 邮箱规范化 | 当前主要规范化域名大小写 | 明确服务商规则，谨慎处理 Gmail 点号和 `+tag`，避免错误合并不同账户 |
| URL 提取 | 支持 `http/https` 提取与去重 | 增加 `mailto:`、裸域名、查询参数保留策略和按域名分组 |
| 日期计算器 | 已有日期加减与时间差 | 增加工作日、周末策略和用户提供的节假日集合 |
| 图片 OCR | 已有本地 OCR 和区域识别，语言范围与 Oltool 不同 | 暂不扩展语言、模型或功能；仅维护现有能力 |

Numeronym 的证据链：`src/lib/tools/text.js` 的 `numeronym()` → `src/lib/TextWorkbench.svelte` 的转换分组和执行分支 → `src/lib/viewRegistry.js` 的 `whitespace` 视图注册；`textActions.js` 和 `searchIntent.js` 同时提供搜索路由。它不是未接入界面的孤立函数。

## 6. 修订后的实施梯队

### P0：先修正基线与发布门禁

原计划把 P0 目标写成 `0.2.0`，但当前清单版本为 `0.1.5`。版本号不应由这份对比文档替项目决定，下一版本应按实际发布策略递增。

1. 修正 README 的“64 个工具入口”，建议同时公布“69 个独立工具入口 / 89 个可见启动入口”，避免以后再次混淆。
2. 固化目录计数测试，分别检查全部定义、可见入口、快捷入口和隐藏父工作台。
3. 对部分覆盖能力说明边界；OCR 保持现状，不纳入扩展排期。
4. 运行前端检查、Rust 测试、构建、DBX 预检和 `.dbxp` 内容检查。
5. 验证 OCR 模型按需下载、哈希校验、失败恢复和离线回归。
6. 继续检查敏感输入不会进入偏好、日志、事件或 Workbench context。

#### P0 发布门槛

- `npm run check` 通过。
- Rust 后端测试与构建通过。
- DBX 项目预检通过。
- 目标平台候选包可生成并通过内容检查。
- 69 个独立入口和 20 个快捷入口均可由目录或搜索访问。
- README、manifest、商店元数据与实际版本一致。

### P1：开发者核心差集

优先复用现有工作台，保持本地处理：

1. 结构化 JSON Diff
2. YAML 树形查看器
3. 新增 Basic Auth 工具：输入用户名、密码，生成可复制的 `Authorization: Basic …`，离开页面清除凭据；反解作为可选后续能力
4. SafeLink 解码
5. 正则表达式速查表
6. Wi-Fi 二维码
7. 罗马数字转换
8. MAC 地址生成器
9. IPv6 ULA 生成器
10. IPv4 范围展开与最优 CIDR 汇总
11. Excel 转 HTML
12. Excel 转纯文本

旧 P1 中的 MIME 查询、随机端口、图片圆角和图片边框已经完成，不再重复排期。

### P2：Calculator Suite

建立统一计算器工作台，共享数值输入、精度、公式展示、复制和错误处理：

1. 数学表达式
2. 单位换算
3. 百分比
4. 数值统计
5. 工作日 / 节假日日期计算
6. 温度转换
7. ETA
8. 秒表与计次
9. Benchmark 对比
10. 复利

数学表达式不得使用 `eval` 或 `new Function`；统计必须区分样本与总体；复利结果必须注明不含税费和产品费率。

### P3：安全与内容专项

#### 安全

1. Bcrypt 哈希与验证
2. 密码强度分析
3. IBAN 校验
4. BIP39 助记词生成与验证

BIP39 必须使用审计过的实现，助记词、可选口令和种子不得持久化，页面离开时清除敏感状态。

#### 内容

1. 新增 Figlet 字体横幅生成，支持内置字体、宽度和对齐
2. 基于现有实现完善 Numeronym 的入口与说明，并补完整英文单复数、邮箱规范化和 URL 提取
3. Emoji 选择器
4. 配色方案生成
5. HTML 富文本编辑器

AI 提示词生成器继续暂缓；如果实现，只做离线静态模板，不引入在线模型依赖。

### P4：GIF 与媒体

1. GIF 压缩
2. GIF 裁剪
3. GIF 帧提取、删除和重排
4. GIF 尺寸、帧率、颜色数和循环次数调整
5. 文字转语音能力检测和朗读

GIF 解码和编码应进入 Worker，并限制输入体积、总像素、帧数和解码内存。摄像头录制继续等待 DBX WebView 媒体权限流程验证。

### P5：PDF 基础工作台

1. 合并与拆分
2. 页面旋转、删除、提取、裁剪和拖拽排序
3. 文字水印和页码
4. 手写或图片签名

所有操作生成新文件，不覆盖原文件。图片签名必须明确标注为视觉签名，不等同于数字签名。

### P6：PDF 高级能力或独立插件

1. PDF 转 PNG / JPEG
2. PDF 压缩
3. PDF 密码加密与已知密码解密
4. PDF 数字签名检查

如果 PDF.js、WASM 或原生依赖显著增加包体、冷启动和跨平台构建成本，应拆成独立插件。数字签名检查必须分别报告内容完整性、证书有效期、证书链、时间戳和系统信任，不能把“可解析”显示成“可信”。

### P7：默认暂缓的联网工具

| 工具 | 暂缓原因 | 可选替代方案 |
| --- | --- | --- |
| 公网 IP 与地理位置查询 | 必须把出口地址交给外部服务 | 不加入，或以后做明确的可选联网功能 |
| DNS / DoH 查询 | 需要外部解析服务或 Sidecar 网络访问 | 可提供系统解析器模式，但必须说明与 DoH 的差异 |
| MAC 厂商查询 | 在线数据需要联网，离线数据需要持续更新 | 内置带版本号的压缩 IEEE OUI 数据集 |
| 在线 AI、翻译、OCR API | 会发送用户内容 | 不纳入，继续使用本地能力 |

## 7. 推荐顺序

```text
P0 修正计数、文档和发布门禁
  → P1 补开发者核心差集
  → P2 Calculator Suite
  → P3 安全与内容专项
  → P4 GIF 与媒体
  → P5 PDF 基础
  → P6 PDF 高级或独立插件
  → 最后重新评估 P7 联网工具
```

总体上，不建议以追平 158 个页面为目标。近期最有价值的是先消除“目录数字失真”，再补 JSON Diff、YAML Viewer、网络地址工具和 Excel 导出；PDF 仍应作为独立的大模块评估。
