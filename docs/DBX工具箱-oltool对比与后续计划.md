# DBX 工具箱与 Oltool 对比及后续实施计划

> 调研日期：2026-10-12  
> 对比对象：[Oltool 程序员工具箱](https://oltool.net/)  
> 本地项目：`dbx-plugin-toolbox`

## 1. 调研结论

Oltool 当前展示 158 个工具。本地 DBX 工具箱实际注册 64 个工具入口，但两者的功能颗粒度不同：Oltool 倾向于把每个小能力拆成独立页面，本地项目则把 JSON、文本、图片、二维码、Excel 等能力合并为综合工作台。

按实际能力而不是页面数量计算，本地已经覆盖约 95–100 个 Oltool 工具对应的能力；明确缺少或没有等价入口的能力约 60 项。

后续不建议为了追求数量机械拆页，应继续遵循以下原则：

- 本地优先，默认不增加网络权限。
- 优先扩展现有工作台，避免重复页面和重复逻辑。
- 密码、密钥、令牌、助记词等敏感输入不得持久化或写入日志。
- 大文件、图片、GIF、OCR 和 PDF 必须设置输入大小、像素、帧数和内存上限。
- 每个新增工具都必须接入目录、搜索、国际化、输入限制、测试和演示体系。

## 4. 实施梯队

## P0：现有基线收口

建议目标版本：`0.2.0`

当前改动规模较大，应先完成以下工作，再继续添加工具：

1. 完成 OCR、GIF、图片、Utility Suite、密钥生成和目录重构。
2. 核对 64 个工具的目录注册、视图加载、输入限制和执行模式。
3. 完成所有支持语言的国际化覆盖。
4. 更新 README 中已经过期的工具数量和功能说明。
5. 检查 OCR 模型和 GIF 依赖对安装包体积的影响。
6. 验证 `host.binary`、`host.events` 的实际调用和最小权限。
7. 验证敏感输入不会进入偏好设置、日志或 Workbench context。
8. 完成前端测试、Rust 测试、构建、预检和 `.dbxp` 安装验证。

### P0 发布门槛

- `npm run check` 全部通过。
- Rust 后端测试与构建通过。
- DBX 项目预检通过。
- Windows、macOS、Linux 完成基础打包验证。
- 所有懒加载工具能够正常打开。
- OCR、GIF 和大图片处理无明显内存泄漏。
- 所有工具均可通过搜索、目录和快捷启动器访问。

## P1：开发者核心补齐

建议目标版本：`0.3.0`

这一阶段全部保持本地处理，不新增网络权限。

### 数据与 Web

1. 结构化 JSON Diff
2. YAML 树形查看器
3. MIME 类型双向查询
4. Basic Auth 生成与反解
5. SafeLink 解码器
6. 正则表达式速查表
7. Wi-Fi 二维码
8. 罗马数字转换

### 网络

9. MAC 地址生成器
10. 随机端口生成器
11. IPv6 ULA 生成器
12. IPv4 范围展开与最优 CIDR 汇总

### 表格与图片

13. Excel 转 HTML
14. Excel 转纯文本
15. 图片圆角
16. 图片边框

### 推荐复用关系

- JSON Diff 与 YAML Viewer 合入 JSON / 数据工作台。
- MIME、Basic Auth、SafeLink、正则速查使用 Utility Suite 模式。
- 网络生成器合入网络/CIDR 工作台。
- Excel 导出扩展现有电子表格页面。
- 圆角和边框作为图片编辑操作。
- Wi-Fi QR 合入现有二维码页面。

## P2：Calculator Suite

建议目标版本：`0.4.0`

建议建立统一计算器工作台，共享数值输入、精度、公式展示、复制和错误处理。

1. 数学表达式计算器
2. 单位换算器
3. 百分比计算器
4. 数值统计计算器
5. 日期和工作日计算器
6. 温度转换器
7. ETA 计算器
8. 秒表与计次
9. Benchmark 结果对比
10. 复利计算器

### 关键约束

- 数学表达式不得使用 `eval` 或 `new Function`。
- 统计计算明确区分样本与总体口径。
- 工作日默认只排除周末，节假日由用户输入。
- 复利结果注明不含税费、费率且不构成金融建议。
- 秒表默认只保存在当前会话。

## P3：安全与内容专项

建议目标版本：`0.5.0`

### 安全工具

1. Bcrypt 哈希与验证
2. 密码强度分析
3. IBAN 校验
4. BIP39 助记词生成与验证

BIP39 必须使用审计过的实现，助记词、可选口令和种子不得持久化，页面离开后应清除敏感状态，并明确警告用户不要在不受信任环境中处理真实资产。

### 内容工具

5. Emoji 选择器
6. 配色方案生成
7. ASCII / Figlet 横幅
8. Numeronym
9. 英文单复数
10. HTML 富文本编辑器

AI 提示词生成器暂缓，只在以后考虑离线静态模板模式。

## P4：GIF 与媒体专项

建议目标版本：`0.6.0`

1. GIF 压缩
2. GIF 裁剪
3. GIF 帧提取
4. GIF 帧删除和重排
5. GIF 尺寸、帧率和循环次数调整
6. 文字转语音能力检测和朗读

GIF 解码与编码应进入 Worker，并限制输入体积、总像素、帧数和解码内存。摄像头录制应等 DBX WebView 媒体权限流程验证完成后再决定是否加入。

## P5：PDF 基础工作台

建议目标版本：`0.7.0`

优先实现不依赖复杂加密和证书验证的能力：

1. PDF 合并
2. PDF 拆分
3. 页面旋转
4. 文字水印
5. 添加页码
6. 删除页面
7. 页面拖拽整理
8. 提取页面
9. 页面裁剪
10. 添加手写或图片签名

PDF 工作台应提供文件列表、页面缩略图、拖拽排序、页码范围输入、处理进度和输出文件信息。所有操作生成新文件，不覆盖原文件。图片签名必须明确标注为视觉签名，不等同于数字签名。

## P6：PDF 高级能力

建议目标版本：`0.8.0`，或拆分为独立 PDF 插件。

1. PDF 转 PNG / JPEG
2. PDF 压缩
3. PDF 密码加密
4. 已知密码 PDF 解密
5. PDF 数字签名检查

如果 PDF.js、WASM 或原生依赖显著增加包体、冷启动时间和跨平台构建成本，应将 PDF 模块拆成独立插件。

数字签名检查必须分别报告：

- 文件内容是否被修改；
- 签名证书是否过期；
- 证书链是否完整；
- 时间戳是否有效；
- 当前系统是否信任签发机构。

不得把“能够解析签名”显示成“签名可信”。

## P7：默认暂缓的联网工具

以下工具会改变当前本地优先和数据不离机的产品承诺：

| 工具 | 暂缓原因 | 可选替代方案 |
| --- | --- | --- |
| 公网 IP 与地理位置查询 | 必须把用户出口地址发送给外部服务 | 不加入，或以后做明确的可选联网功能 |
| DNS / DoH 查询 | 需要外部解析服务和精确网络权限 | 可使用 Sidecar 调系统解析器，但语义与 DoH 不同 |
| MAC 厂商查询 | 在线查询需要网络，离线数据集需要持续更新 | 内置带版本号的压缩 IEEE OUI 数据集 |
| 在线 AI、翻译、OCR API | 会发送用户内容 | 不纳入，继续使用本地能力 |

当前插件只使用 `host.binary` 和 `host.events`，后续 P0–P6 均不计划新增 `host.network`。

## 5. 推荐实施顺序

```text
P0 稳定当前 64 工具基线
  → P1 开发者核心补齐
  → P2 Calculator Suite
  → P3 安全与内容专项
  → P4 GIF 与媒体
  → P5 PDF 基础
  → P6 PDF 高级
  → 最后重新评估 P7 联网工具
```

## 6. 每个里程碑的固定交付门禁

1. 完成功能和纯逻辑单元测试。
2. 接入目录、搜索别名、快捷启动、演示数据和输入限制。
3. 完成全量国际化检查。
4. 验证明暗主题、键盘导航、焦点顺序、屏幕阅读器和窄屏布局。
5. 运行 `npm run check`。
6. 涉及 Sidecar 时运行 Rust 测试和构建。
7. 运行 DBX 项目预检。
8. 生成未签名 `.dbxp` 并检查包内容。
9. 在本地 DBX 安装和回归验证。
10. 增加 SemVer 版本号并发布新的候选包，不覆盖旧版本资产。

## 7. 总体建议

近期最重要的工作是完成 P0 收口。当前工作区已有大量跨模块改动，如果此时继续加入 PDF、Bcrypt 或 Calculator Suite，会显著增加回归和发布风险。

在 P0 稳定后，P1 的 16 项能力最符合开发者工具箱定位，而且能够最大程度复用现有工作台。P2 和 P3 可以继续保持纯前端、本地计算。PDF 应作为独立大模块评估，不应为了追齐 Oltool 的页面数量而仓促加入。

整个路线应继续遵循 DBX 插件的权限最小化原则：敏感数据不出本机、不进入日志，网络权限只有在存在明确用户价值且能够精确限定目标域名时才考虑增加。
